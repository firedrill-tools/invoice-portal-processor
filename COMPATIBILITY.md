## Ownership, bounds and private records

The owner aborts new operations at a configurable deadline up to 120 seconds, clears its timer/parent listener and closes browser resources. Provider HTTP 15 seconds; portal read 5 seconds; browser actions/navigation 5 seconds and startup 10 seconds. Each browser close step has 5 seconds, with bounded kill fallback; final source audit has its own 5 second cleanup budget. Filesystem flush/publication is awaited, so these are dispatch/operation bounds rather than a hard total wall-clock promise. Node's global fetch pool and an injected caller's connections remain their owners' resources; only owned operations/signals/readers are stopped.

Limits are 18 prepared provider requests/rounds, 1800 requested output tokens, 32 calls/message and 128 accepted tool calls, 1 MiB provider request/retained decoded response, 129 observations, 4 MiB retained viewport PNG, 6000 page-text characters and 40 controls (2000 characters/value). Form intent is capped at 16 KiB; input task at 2000 characters. Capture limits do not establish compressed-wire traffic, peak heap or billing limits.

Each run directory is newly 0700 and trace/PNG files 0600; existing parents retain their modes. Unique staged files flush before atomic replacement and parent sync. Receipts bind task/instruction/source hashes, initial/final portal facts, original HTTP and SDK/client reports, prepared actions/results, browser HTTP intent/acknowledgements and lifecycle/effects. Screenshots are real viewport captures with hashes. Source API snapshots validate complete schema1 and cross-history bindings; initial/final continuity is checked. Source capture is separately bounded to 1MiB, while the local JSON store permits 8MiB and bounded collection counts.

Recording failures latch and prevent subsequent actions. Native in-flight operations and browser evidence queues drain before final publication; cancellation during a delayed original-response write leaves a stable final receipt. Failed receipts retain actual effects and errors; final storage failure gets a best-effort failed write. If publication cannot be confirmed, the caller receives failure and the last durable file can be uncertain. Never treat the model's prose alone as committed-state proof.
