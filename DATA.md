# Synthetic invoice cases and private CLI

Dataset `ledgerline-invoice-workspace` version1.0.0 has twelve byte-bound cases across four profiles. `data/manifest.json` lists each case's ID/profile/file/SHA256 and human task/focus. Case envelopes bind the family/version/case/profile to a complete schema1 state. All metadata, bytes and original human/source relationships are validated before listing or initialization. The original five-document legacy starter remains in `fixtures/starter.json` for migration proof.

| Case | Profile | Business situation |
| --- | --- | --- |
| starter | starter | Five invoices; exact approved DOC-001 |
| busy | busy | Eight vendors, 36 documents and twelve prior human imports; target DOC-001 is last |
| ambiguous-vendor | ambiguous | Same vendor name/invoice number, two distinct vendor/source IDs |
| canonical-duplicate | ambiguous | Retired human entry uses a case variant of the same invoice identity |
| already-recorded | boundary | Original human entry predates changed values and revoked source approval |
| missing-field | boundary | Missing due date |
| mismatched-total | boundary | Subtotal plus tax differs from original total |
| pending-approval | boundary | Approval is pending |
| invalid-date | boundary | Readable impossible Gregorian issue date |
| unsupported-currency | boundary | JPY requires unsupported minor-unit semantics |
| large-cents | boundary | MAX_SAFE_INTEGER-1 exact cents; zero tax |
| empty-inbox | boundary | No source/vendor rows; original retired human entry remains |

Busy spans CAD/USD/EUR/GBP and noncontiguous ENT-0002…ENT-0079 original IDs. Each imported record has complete original approved source/vendor/value/time and a fictional human-import label. One vendor name contains a quoted instruction as untrusted business text. No previous model output, provider usage, operator requests or fabricated portal audit events are seeded. Ambiguity requires a human source/vendor decision; no runtime label chooses an answer.

## Key-free commands

Requires Node24+. Parent directory must exist. Every initialization owns a new private leaf, never an existing destination.

```sh
npm run cases -- list
mkdir -m 700 local-cases
npm run cases -- init busy local-cases/busy
npm run cases -- show local-cases/busy
INVOICE_WORKSPACE_FILE=local-cases/busy/workspace.json npm run portal
```

Use `--data-root PATH` once to select an alternative complete validated bundle. `--help` does not read data or require provider configuration. Arguments/options are strict; unknown/duplicate options and extra positional arguments fail. Listing and initialization validate all cases, including exact hashes/identity/schema, before creating a destination. Parent paths must exist, and private cases must be outside bundled data. Existing directories/files/symlinks fail exclusively; no source or persistent mutex is overwritten.

The new directory is0700; `workspace.json` and `case.json` are0600 and flushed with directory sync. Initialization preserves every original business fact but assigns a fresh workspace UUID. Thus review tokens from separate copies are incompatible. `case.json` records case digest, initial private-state hash, fresh instance and initialization time. Template instances are deterministic generation identities, not historical model runs.

`show` validates case provenance and complete current state under its persistent source mutex. It reports initial/current hashes and whether source state has changed. Source JSON remains unchanged by show; the mutex sidecar may be created. Invalid/replaced legacy/foreign state is refused without migration or repair. Historical entries and corrected current source are read as distinct original facts.

Tasks/focus appear only in the human manifest/CLI output. The portal source API and implicit model instructions contain business state; they do not ingest dataset tasks/focus. Choose and pass a human task explicitly to `npm run operate -- "..."`. Model/provider quality must be reviewed separately from these controlled fixtures.

To reset, initialize another new directory. Keep the original source, request receipts and persistent mutex inode attached to the old case for uncertain-effect recovery.

## Reproduce and distribute

`npm run data:generate` reproduces the manifest/case bytes from `scripts/generate-data.js`. An optional positional output directory generates an independent bundle without modifying the checkout. The test suite compares all generated bytes with the committed bundle and exercises every private initialization, original-history preservation, business conflicts, corrupt/unsafe bundles, collisions and key-free commands.

`npm run check:distribution` builds `dist/invoice-portal-processor-0.2.0-source.tar.gz`, its SHA256 and a qualification report. Python3.9+, Node24+, npm and Playwright's Chromium/system dependencies are required. CI installs browser/system dependencies first. The archive includes all application/UI source, fixtures/cases, scenarios, scripts/tests, env example, plans/contracts, workflow and locked dependencies. It excludes installed dependencies, keys, generated private cases/receipts, Git and output artifacts.

The verifier checks every archive member/hash, extracts outside the checkout, performs a fresh locked install, resolves the actual SDK/browser/server locally, installs the declared Chromium, exercises all help/list/init/show/collision/key-negative paths and runs the complete native/browser/source/concurrency/normal-CLI suite. Actual normal operator CLI proofs use an owned loopback HTTP provider with synthetic responses, including provider failure and SIGINT/SIGTERM/SIGHUP; no paid model is called. Archive timestamps/modes/ordering/gzip header are deterministic. Live semantic quality, billing, new Firedrill integration and publication/license remain separate gates.
